## Classification legend

| Status | Meaning |
|---|---|
| keep | Still valid as-is for the private control-plane workspace. |
| adapt | Keep the asset but update semantics, references, or callers for just-chill. |
| rename | Move or rename later to just-chill terminology while preserving history. |
| deprecate | Keep as predecessor/reference, but do not treat as the canonical current path. |
| remove | Remove only after explicit approval and traceable replacement. |

## Migration stance

The safe path is staged adaptation, not a big-bang rename:

1. Keep predecessor docs and compatibility tests.
2. Route new just-chill behavior through explicit scripts and harnesses.
3. Convert legacy executor routing to just-chill/GJC policy only after bridge plans and live bindings are validated.
4. Add real Hermes/GJC adapters behind the contract skeletons rather than embedding host-specific assumptions in portable scripts.

## Unresolved compatibility risks

- Hermes CLI is available, memory status is readable, and `just_chill_memory_api` is registered as a host-owned MCP server exposing raw artifact, RDF graph, and vector sidecar lifecycle tools; host-owned lifecycle receipts now prove create/read/search/delete semantics, while Hermes-native summary receipt/audit APIs are still unmapped.
- `just_chill_harness` is registered in Hermes and exposes the Hermes-facing `just_chill.*` policy tools; a new Hermes session is required before using newly registered tools.
- RDF/OWL and SHACL are deterministic contract-level JSON with host-owned persistence plans; local RDF parsing support, live `pyshacl`, and Hermes RDF graph lifecycle tools exist, and receipt fixtures prove live SHACL + RDF graph read-back/delete evidence. Real canonical promotion still requires approved source artifacts/candidates.
- Vector sidecar and recall gates now exist as deterministic contracts over Hermes-canonical refs/hashes, and the host-owned `just_chill_memory_api` maps exact-hash/source-id sidecar create/search/read/delete tools. Holographic `fact_store(search/probe/list)` remains provider summary search, not vector sidecar authority.
- A non-sensitive migration fixture now proves repo-wiki design facts can replay through raw/RDF/vector Hermes MCP lifecycles and summary receipts without private memory promotion; real personal memory migration still requires explicit source selection and approval.
- A safe user-facing CLI wrapper now exists for route/remember/recall/handoff-gjc contract output. It is not an executor: it records mutation requests but keeps execution disallowed until a host-owned visible session, coordinator, delegation, or RPC bridge consumes the contract and returns durable evidence.
- Coordinator/delegation execution has a deterministic consent policy. Even when coordinator smoke and delegate tools are present, mutation remains blocked until required mutation classes and per-call `allow_mutation` are supplied and durable non-scrollback evidence is required.
- An end-to-end dogfood contract harness now proves the integrated route -> memory/raw/RDF/SHACL/vector -> recall -> GJC handoff/consent chain without hidden execution, and fail-closes on stale recall evidence or sensitive memory.
- Repo-local visible routed-session helpers exist, pass contract probes, and emit dry-run tmux/GJC argv plans when `tmux` and `gjc` are available; real operator-executed tmux/TUI orchestration is still a separate bridge extension.
- Coordinator MCP smoke check passes and `gjc_delegate_*` tools are present in the coordinator tool list, but the consent policy remains the gate for any executable coordinator/delegation use.
- No live RPC host `customTools` registry is mapped yet.
- Existing Codex/OMX routing assets still exist as predecessor policy and may conflict with just-chill if a caller bypasses the new router.
