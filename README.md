# JARVIS Control Plane

This workspace is the central control plane for the user's Hermes-centered JARVIS workflow.

## Roles

- Hermes Agent: orchestrator, planner, verifier, memory/skill manager, wiki maintainer.
- Codex CLI + OMX: implementation executors for medium/large coding work.
- Obsidian Wiki: human-readable project memory, decisions, status, and architecture notes.
- `/home/hskim/projects`: WSL-native development repositories.

## Core paths

- `AGENTS.md`: standing operating rules for Hermes/JARVIS sessions launched here.
- `config/projects.yaml`: project registry.
- `config/routing.yaml`: executor routing policy.
- `harnesses/`: reusable execution procedures.
- `plans/`: implementation and migration plans.
- `runs/`: run logs and executor summaries.
- `wiki/`: Obsidian-readable long-term project knowledge.
- `scripts/`: helper scripts.
- `logs/`: local logs generated by JARVIS workflows.
- `tmp/`: temporary files scoped to this control plane.

## Starting Hermes

From WSL:

```bash
cd /home/hskim/jarvis
hermes
```

For project implementation, Hermes should execute Codex/OMX in the target repo, for example:

```bash
omx exec -C /home/hskim/projects/<project> "<approved implementation prompt>"
```

## Safety baseline

Hermes config is expected to use:

- `approvals.mode: smart`
- `approvals.cron_mode: deny`
- `security.tirith_enabled: true`
- `security.redact_secrets: true`

Never expose or store API keys, OAuth tokens, auth.json contents, SSH private keys, or secrets in this workspace.
